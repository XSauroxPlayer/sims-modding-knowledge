# TS3 CLIP (0x6B20C4F3) - binary layout

Wiki says "Reasonably accurate and tested"; core decoded by Karybdis. Same data as the s3pi `ClipResource.cs`
parser (see `topics/clip-format.md`).

## Names and age variants
- Clip name forms: `x_anim_name` (one actor) and `x2y_anim_name` (actor x on target y).
  `a_`, `a2a_`, `a2o_` are the fallbacks when a requested age variant (e.g. `t2c_...`) is missing.
- Instance hash: if every actor letter is `a` or `o`, FNV64 of the name with the top bit cleared. Otherwise replace the
  non-`o` letter with `a`, hash, set the top bit and XOR the age mask into the top byte (actor) / 2nd byte (target).
- Age masks: b 0x01, p 0x02, c 0x03, t 0x04, h 0x05, e 0x06, ad 0x08, cd 0x09, al 0x0A, ac 0x0D, cc 0x0E, ah 0x10,
  ch 0x11, ab 0x12, ar 0x13 (the page gives only the letters; ad/cd = adult/child dog, al = little dog, ac/cc = cats,
  ah/ch = horses is an interpretation, not on the wiki).

## Main header (offsets are relative to the position of the offset field itself)
`TID`, linked-clip offset (always 0), S3Clip section size, `clipoffset`, `slotoffset` (actor/slot = IK table),
`actoroffset` (actor name, null-terminated, padded to DWORD with 0x7E), `eventoffset`, DWORD 0 or 2, DWORD 1,
`endoffset`, 16 blank bytes.

## S3Clip header
- QWORD magic `_S3Clip_` (stored as integer), version 2, blank DWORD, FLOAT frame duration (always 1/30),
  WORD frame count ("not necessarily the number of frames"), WORD unknown, count of joint tracks, count of indexed
  floats, offset to tracks, offset to frame data, offset to anim name, offset to **source file name**.
- The source file name matters: Jazz `Assign Actor "<source>.ma"."x"` uses it to map Jazz actors to clip actors.

## Tracks (joint movement rules)
`frame data offset`, `hash` (FNV32 of bone name; for pet face morphs FNV64 of the 0x0A037DDA morph name, folded to 32
bits), FLOAT offset, FLOAT scale, WORD keyed frame count, WORD data type.

Frame data: WORD frame index (frames can be skipped), WORD sign bits (bit n = sign of value n, applied to every value,
float ones included), then type data. Integers decode as value / max (4095, 1023), then `* scale + offset`.

| type | data | use |
|---|---|---|
| 0x103 | 3 WORD | indices into the indexed-float table |
| 0x10B | none | null translation |
| 0x112 | DWORD, 3 x 10 bit | translation |
| 0x20C | none | null rotation |
| 0x211 | ? (count 0) | indexed float reference? |
| 0x214 | DWORD-ish, 12-bit values | quaternion, order XYZW; "framework requires +90 degree rotation" |
| 0x705 | WORD | Pets: scalar morph value / 0xFFFF, then scale/offset |
| 0x709 | none | Pets, unknown |

## Actor/slot table (= IK targets)
DWORD-aligned (0x7E pad). Primary entries = one per **rig IK chain**; each has a `0x7E7E7E7E` pad, then secondary
entries: `index`, 512-byte actor name and 512-byte slot name, both null-terminated and padded with `#` (0x23).
"Secondary entries are IK targets used in the animation." The page notes the named actor "may or may not be the actor
for the animation".

## Events
Section magic `=CE=`, version 0x103, count, size, start offset (4 if count > 0). Each event: WORD type, WORD 0xC1E4,
DWORD id, FLOAT time (seconds), FLOAT -1, FLOAT -1, DWORD, DWORD name length, name (null + pad to DWORD), payload:

| type | meaning | payload |
|---|---|---|
| 1 | attach prop to slot (parent) | hash prop actor, hash object actor, hash slot on object, blank, 16 floats (identity 4x4) |
| 2 | unparent ("mostly the bath ducky") | hash actor to unparent |
| 3 | sound | 128-byte sound name; bytes after the string are uncleared memory |
| 4 | SACS script event | none; the event `id` is what game script receives |
| 5 | effect | DWORD, DWORD, hash effect name, hash actor, hash slot/bone |
| 6 | visibility | FLOAT 0.0..1.0 |
| 9 | destroy prop | hash of a prop created with Jazz `Create Prop` |
| 10 | stop effect | hash effect name, blank DWORD |

## End data
16 bytes pointed to by `endoffset`: 12 zero bytes + FLOAT 1.0 (`0,0,0,1`, "perhaps a quaternion").

## Notes vs other sources
- Event type 1 field order: wiki says (prop actor, object actor, slot); s3pi names them (ActorNameHash, ObjectNameHash,
  SlotNameHash) which reads as (actor the event plays on, prop/child, parent slot).
  **CONTRADICTION in naming only**; check against an EA clip before relying on the order.
- Frame rate 1/30 s agrees with clips written by the project author's converter that play correctly in game.
